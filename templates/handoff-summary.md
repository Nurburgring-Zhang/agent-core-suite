# 交接总结模板（跨步 / 跨轮 / 跨会话唯一允许的传递载体）

> 硬约束：正文 **≤1000 字硬上限**（目标 ≤400 字省 token；不含本说明与代码块内命令）。超上限即违反回灌禁令。
> 三要素无损：`当前目标` / `已完成项` / `下一步` 缺一不可，且必须非空话；另需 `当前目标` 锚点 + 偏离自检（`drift_checked`）防跑偏。
> 由 `scripts/gate_checklist.py` 的 `STEP_handoff` 机检：跳过 / 空话 / 超字数 / 无目标锚点 / 未自检 一律 BLOCK（阈值见 `spec/thresholds.json` 的 `handoff` 节）。
> 下一步只允许读：本总结 + `task-state.json` + 明确列出的文件路径。**不得回灌完整历史。**

---

## 用法

1. 每完成一个节点/步骤，覆盖写 `.acs/handoff.md`（只保留最新一份，历史进 `task-state.json` 的 `steps[]`）。
2. 下一步开工前，先读 `.acs/handoff.md`，再按「下一步入口」里的路径**定点读取**，禁止全量重扫。
3. 写完立即自检：`python -X utf8 scripts/gate_loop_guard.py --state .acs/task-state.json --tier <T1|T2|T3>`

## 模板（六段，逐段填，禁止增段）

```markdown
## 0 当前目标（锚点，每步复述防跑偏）
- 总目标：<一句话，跨步不变>
- 本步唯一目标：<单一目标，禁止「并且/同时」>
- 偏离自检：drift_checked=true（已比对总目标，未跑偏）

## 1 已确认事实（只写被证据支撑的，每条附证据）
- <事实>｜证据：<命令 + 退出码 / 文件:行 / 断言名>
- <事实>｜证据：<...>

## 2 已完成产出（文件路径 + 一句话作用）
- `<path>`：<作用>
- `<path>`：<作用>

## 3 未解决问题 / 已知风险（含已排除的错误路径，防重复踩坑）
- <问题>｜已尝试：<方案A 失败原因>｜不要再试：<...>

## 4 下一步入口（唯一目标 + 完成标准 + 需读文件清单 ≤5）
- 目标：<单一目标，禁止「并且/同时」>
- 完成标准：<可机检：命令 + 期望退出码 / 文件存在 / 断言通过>
- 需读：`<path1>`、`<path2>`（≤5 个）

## 5 状态指针
- 状态文件：`.acs/task-state.json`（tier=<T?>，round=<n>，node=<id>）
- 验证记录：`.acs/verify-record.json`（如有）
```

## 反例（以下写法一律视为违规）

| 违规写法 | 为什么违规 | 改法 |
| --- | --- | --- |
| 「详见上文分析」 | 强迫下一步回灌历史 | 把结论抄进第 1 段，附证据 |
| 「继续完善剩余部分」 | 目标不唯一、不可机检 | 写成单一目标 + 可执行完成标准 |
| 「代码基本没问题」 | 空话，无证据 | 写「pytest 107 passed，exit=0」 |
| 粘贴 200 行日志 | 违反 400 字与上下文体积闸 | 写「日志见 `logs/x.log:120-140`，结论：<一句>」 |
| 「需要读整个项目了解一下」 | 读取预算失控 | 列 ≤5 个具体文件路径 |

## 自检清单（写完逐条打勾）

- [ ] 正文 ≤1000 字（目标 ≤400 字）
- [ ] 第 0 段目标锚点在位，`drift_checked=true`（未跑偏）
- [ ] 第 1 段每条事实都有可复核证据（命令/文件行/断言）
- [ ] 第 4 段目标唯一，完成标准可机检
- [ ] 需读文件 ≤ 5 个，且都是具体路径
- [ ] 全文不含「上文 / 前文 / 之前的讨论 / 如前所述 / 相关背景」
- [ ] 已同步更新 `task-state.json` 的 `steps[].handoff`（结构化镜像）与 `summary_chars`
- [ ] 已写本步 `steps[].review`（双AI自对抗审核：reviewer≠builder、verdict、issues 闭环、self_check）
- [ ] `gate_checklist.py --tier <T?>` 退出码 0（STEP_handoff + STEP_self_review 均过）
